BÁO CÁO PHÂN TÍCH HỆ THỐNG VÀ KẾ HOẠCH TRIỂN KHAI GLOBAL EXCEPTION HANDLING BẰNG @RestControllerAdvice
Dự án: Hcomic Spring Boot Backend

--------------------------------------------------------------------------------
PHẦN 1: THỐNG KÊ TOÀN BỘ EXCEPTION ĐANG SỬ DỤNG TRONG DỰ ÁN
--------------------------------------------------------------------------------

1.1. IllegalArgumentException
- Xuất hiện ở đâu:
  + UploadUtils.java (dòng 28, 33, 38, 47): khi file upload rỗng, tên file không đúng định dạng, đuôi file không thuộc (jpg, jpeg, png, gif, webp), nội dung file ảnh không đọc được.
  + ComicServiceImpl.java (dòng 37): khi title của truyện rỗng/null.
  + CommentServiceImpl.java (dòng 32, 52): khi content của comment rỗng/null.
  + ComicRateServiceImpl.java (dòng 37, 40): khi request/comicId null hoặc điểm đánh giá không nằm trong khoảng 1-5.
- Dùng để làm gì: Kiểm tra (validate) tham số đầu vào của các phương thức.
- Đánh giá tính hợp lý:
  + Tương đối hợp lý về mặt ngữ nghĩa (tham số không hợp lệ).
  + Tuy nhiên, việc validate thủ công trong Service dẫn đến code trùng lặp. Giải pháp tốt hơn là sử dụng Bean Validation (Jakarta Validation: @NotBlank, @NotNull, @Min, @Max) ngay trên DTO request kết hợp với @Valid ở Controller.
  + Ngoài ra, khi IllegalArgumentException bị ném ra mà không có ExceptionHandler tập trung, Controller phải try-catch thủ công và trả về String text plain, làm API response thiếu tính nhất quán.

1.2. RuntimeException (Generic)
- Xuất hiện ở đâu:
  + AuthServiceImpl.java:
    * Dòng 34: throw new RuntimeException("Username is already taken!");
    * Dòng 63: .orElseThrow(() -> new RuntimeException("User not found"));
  + ComicServiceImpl.java:
    * Dòng 56, 134: throw new RuntimeException("Failed to upload comic cover image: " + e.getMessage(), e);
    * Dòng 87, 103, 146, 172: .orElseThrow(() -> new RuntimeException("Comic not found with id: " + id));
    * Dòng 95: .orElseThrow(() -> new RuntimeException("Comic not found with slug: " + slug));
  + CommentServiceImpl.java:
    * Dòng 77, 93: Comic not found with id...
    * Dòng 88: User not found with username...
    * Dòng 98: Comment not found with id...
    * Dòng 103: throw new RuntimeException("You can only " + action + " your own comment");
  + ComicRateServiceImpl.java:
    * Dòng 44, 47, 70: User not found..., Comic not found..., Rating not found...
  + ComicLikeServiceImpl.java:
    * Dòng 68, 73: User not found..., Comic not found...
- Dùng để làm gì: Bắt hầu như tất cả lỗi nghiệp vụ (không tìm thấy dữ liệu, trùng tài khoản, lỗi upload file, vi phạm quyền sở hữu...).
- Đánh giá tính hợp lý:
  + RẤT KHÔNG HỢP LÝ (Anti-pattern).
  + Việc lạm dụng RuntimeException chung chung khiến hệ thống không thể phân loại lỗi (không phân biệt được lỗi 404 Not Found, 400 Bad Request, 403 Forbidden hay 500 Internal Server Error). Khi đẩy lên @RestControllerAdvice sẽ khó trả về đúng HTTP Status Code và message cấu trúc.

1.3. IOException
- Xuất hiện ở đâu: UploadUtils.java (dòng 26, 67).
- Dùng để làm gì: Khai báo checked exception cho các thao tác I/O đọc/ghi file ảnh WebP.
- Đánh giá tính hợp lý: Hợp lý cho lớp Utility làm việc với File I/O. Tuy nhiên ở lớp Service nên được bọc lại bằng một Custom File Exception rõ nghĩa.

1.4. UsernameNotFoundException & AuthenticationException
- Xuất hiện ở đâu: CustomUserDetailsService.java (dòng 25) và JwtAuthenticationEntryPoint.java.
- Dùng để làm gì: Xử lý xác thực người dùng trong Spring Security context.
- Đánh giá tính hợp lý: Hợp lý, chuẩn theo kiến trúc Spring Security.

PHẦN 2: PHÂN TÍCH CONTROLLER
--------------------------------------------------------------------------------

2.1. Liệt kê các Controller đang sử dụng try-catch:
Tất cả 5 Controller hiện tại đều dùng try-catch ở hầu hết các endpoint:
1. AuthController.java:
   - register(): try-catch Exception -> trả về 400 Bad Request string.
   - login(): try-catch Exception -> trả về 400 Bad Request string.
2. ComicController.java:
   - createComic(): try-catch Exception -> trả về 400 Bad Request string.
   - getComicById(): try-catch Exception -> trả về 404 Not Found string.
   - getComicBySlug(): try-catch Exception -> trả về 404 Not Found string.
   - updateComic(): try-catch Exception -> trả về 400 Bad Request string.
   - deleteComic(): try-catch Exception -> trả về 404 Not Found string.
3. CommentController.java:
   - createComment(), getCommentsByComicId(), updateComment(), deleteComment(): try-catch Exception -> trả về 400 Bad Request string.
   - Ngoài ra còn check auth thủ công: if (authentication == null || !authentication.isAuthenticated()) -> trả về 401 string.
4. ComicRateController.java:
   - rateComic(), getUserRating(): try-catch Exception -> trả về 400 Bad Request string.
   - Check auth thủ công trả về 401 string.
5. ComicLikeController.java:
   - toggleLike(), getLikeStatus(): try-catch Exception -> trả về 400 Bad Request string.
   - Check auth thủ công trả về 401 string.

2.2. Có nên bỏ try-catch không?
KẾT LUẬN: NÊN BỎ HOÀN TOÀN try-catch VÀ CHECK AUTH THỦ CÔNG Ở CONTROLLER.

Lý do:
- Vi phạm nguyên lý Single Responsibility (SRP): Controller chỉ chịu trách nhiệm nhận Request, điều hướng tới Service và trả về Success Response. Xử lý lỗi là trách nhiệm của Exception Handler.
- Boilerplate code: Code bị lặp lại ở mọi endpoint.
- Phản hồi không đồng nhất: Lúc trả về DTO JSON Object, lúc trả về chuỗi String plain.
- Hardcode HTTP Status không đúng: Ví dụ trong CommentController, mọi lỗi (kể cả 404 không thấy Comic hay 403 không phải chính chủ) đều bị bắt và trả về 400 Bad Request.

2.3. Nếu bỏ thì GlobalExceptionHandler sẽ thay thế như thế nào?
- Code trong Controller sẽ được rút gọn tối đa:
  Controller chỉ nhận request và return ResponseEntity.ok(serviceResult);
- Khi Service hoặc hệ thống throw bất kỳ Exception nào, Spring MVC sẽ tự động chuyển giao exception đó cho lớp @RestControllerAdvice (GlobalExceptionHandler).
- GlobalExceptionHandler dùng các phương thức @ExceptionHandler(ExceptionType.class) để bắt lỗi, đóng gói thông tin lỗi vào DTO chuẩn (ErrorResponse) và trả về Client đúng HTTP Status Code (400, 401, 403, 404, 500).

PHẦN 3: PHÂN TÍCH SERVICE
--------------------------------------------------------------------------------

3.1. Liệt kê Service nào đang throw RuntimeException:
Cả 5 Service implementation đều đang throw RuntimeException:
- AuthServiceImpl
- ComicServiceImpl
- CommentServiceImpl
- ComicRateServiceImpl
- ComicLikeServiceImpl

3.2. RuntimeException nào nên thay bằng Custom Exception?
- Lỗi không tìm thấy đối tượng (Comic, User, Comment, Rating): Thay bằng ResourceNotFoundException.
- Lỗi dữ liệu trùng lặp / không hợp lệ (Username is already taken): Thay bằng BadRequestException.
- Lỗi vi phạm quyền sở hữu (You can only edit/delete your own comment): Thay bằng ForbiddenException (hoặc AccessDeniedException).
- Lỗi xử lý file upload (Failed to upload comic cover image): Thay bằng FileStorageException.

3.3. Đề xuất Custom Exception thực sự cần thiết (Không tạo thừa):
Chỉ tạo 4 Custom Exception bao quát toàn bộ domain HTTP status của hệ thống:

1) ResourceNotFoundException (extends RuntimeException)
   - Dùng khi nào: Khi tìm kiếm entity trong DB theo ID/Slug/Username mà không có dữ liệu.
   - Throw ở đâu:
     + ComicServiceImpl: getComicById, getComicBySlug, updateComic, deleteComic, increaseView.
     + CommentServiceImpl: findUserByUsername, findComicById, findCommentById, getCommentsByComicId.
     + ComicRateServiceImpl: rateComic, getUserRatingForComic.
     + ComicLikeServiceImpl: findUserByUsername, findComicById.
     + AuthServiceImpl: login (khi tìm User).
   - HTTP Status trả về: 404 NOT_FOUND.

2) BadRequestException (extends RuntimeException)
   - Dùng khi nào: Khi tham số hoặc dữ liệu gửi lên vi phạm quy tắc nghiệp vụ.
   - Throw ở đâu: AuthServiceImpl.register() khi trùng username, hoặc các đoạn validate nghiệp vụ Service.
   - HTTP Status trả về: 400 BAD_REQUEST.

3) ForbiddenException (extends RuntimeException)
   - Dùng khi nào: Người dùng đã đăng nhập nhưng không có quyền thao tác trên tài nguyên (chỉ được sửa/xóa comment của chính mình).
   - Throw ở đâu: CommentServiceImpl.verifyOwnership().
   - HTTP Status trả về: 403 FORBIDDEN.

4) FileStorageException (extends RuntimeException)
   - Dùng khi nào: Lỗi trong quá trình đọc, convert WebP hoặc lưu file lên ổ đĩa.
   - Throw ở đâu: ComicServiceImpl (createComic, updateComic) và UploadUtils.
   - HTTP Status trả về: 500 INTERNAL_SERVER_ERROR.

PHẦN 4: ĐỀ XUẤT DTO TRẢ LỖI THỐNG NHẤT (ErrorResponse)
--------------------------------------------------------------------------------

4.1. Cấu trúc Class DTO đề xuất (com.comic.h.dto.response.ErrorResponse):
```java
package com.comic.h.dto.response;

import com.fasterxml.jackson.annotation.JsonInclude;
import lombok.AllArgsConstructor;
import lombok.Builder;
import lombok.Getter;
import lombok.NoArgsConstructor;
import lombok.Setter;

import java.time.LocalDateTime;
import java.util.Map;

@Getter
@Setter
@Builder
@NoArgsConstructor
@AllArgsConstructor
@JsonInclude(JsonInclude.Include.NON_NULL)
public class ErrorResponse {
    private int status;
    private String error;
    private String message;
    private String path;
    private LocalDateTime timestamp;
    private Map<String, String> validationErrors;
}
```

4.2. Giải thích lý do chọn các field:
- status (int): Mã số HTTP status (400, 404, 403, 500...). Giúp Frontend kiểm tra mã lỗi dễ dàng ngay trong payload JSON.
- error (String): Tên loại lỗi HTTP (vd: "Not Found", "Bad Request", "Forbidden"). Phân loại lỗi cho việc log/debug.
- message (String): Thông báo chi tiết bằng ngôn ngữ dễ hiểu để Frontend hiển thị thông báo (Toast/Alert) cho người dùng.
- path (String): Endpoint URI xảy ra lỗi (vd: "/api/comic/100"). Rất hữu ích cho việc tracing log trên server.
- timestamp (LocalDateTime): Thời gian phát sinh lỗi.
- validationErrors (Map<String, String>): Danh sách lỗi chi tiết theo từng ô nhập liệu khi validate form thất bại (chỉ có khi dùng @Valid). Field này BẮT BUỘC để Frontend binding hiển thị thông báo lỗi dưới từng ô input trong giao diện người dùng.

PHẦN 5: ĐỀ XUẤT CÁC @ExceptionHandler CẦN CÓ TRONG GlobalExceptionHandler
--------------------------------------------------------------------------------

Lớp GlobalExceptionHandler (đánh dấu @RestControllerAdvice) trong package com.comic.h.exception sẽ bao gồm các handler:

1. @ExceptionHandler(ResourceNotFoundException.class)
   - Giải thích: Bắt tất cả lỗi không tìm thấy đối tượng. Trả về HTTP 404 NOT_FOUND + ErrorResponse.

2. @ExceptionHandler({BadRequestException.class, IllegalArgumentException.class})
   - Giải thích: Bắt các lỗi dữ liệu/nghiệp vụ không hợp lệ. Trả về HTTP 400 BAD_REQUEST + ErrorResponse.

3. @ExceptionHandler(MethodArgumentNotValidException.class)
   - Giải thích: Bắt lỗi khi các DTO đính kèm @Valid bị vi phạm các ràng buộc (@NotBlank, @Min, @Max...). Trích xuất tất cả FieldError vào map validationErrors. Trả về HTTP 400 BAD_REQUEST + ErrorResponse.

4. @ExceptionHandler({ForbiddenException.class, AccessDeniedException.class})
   - Giải thích: Bắt lỗi vi phạm quyền hạn truy cập / không phải chủ sở hữu tài nguyên. Trả về HTTP 403 FORBIDDEN + ErrorResponse.

5. @ExceptionHandler(BadCredentialsException.class)
   - Giải thích: Bắt lỗi nhập sai username/password từ AuthenticationManager khi login. Trả về HTTP 401 UNAUTHORIZED + ErrorResponse ("Invalid username or password").

6. @ExceptionHandler(FileStorageException.class)
   - Giải thích: Bắt các lỗi đọc/ghi/convert file ảnh bìa. Trả về HTTP 500 INTERNAL_SERVER_ERROR + ErrorResponse.

7. @ExceptionHandler(Exception.class) (Fallback Handler)
   - Giải thích: Bắt tất cả các lỗi hệ thống không lường trước được (NullPointerException, lỗi SQL...). Ghi log error server và trả về HTTP 500 INTERNAL_SERVER_ERROR với thông báo an toàn, ẩn đi chi tiết nhạy cảm của hệ thống.

PHẦN 6: TỔNG KẾT KẾ HOẠCH REFACTOR
--------------------------------------------------------------------------------

6.1. Controller sẽ được xóa try-catch và code thừa:
- AuthController.java: Xóa try-catch trong register(), login().
- ComicController.java: Xóa try-catch trong createComic(), getComicById(), getComicBySlug(), updateComic(), deleteComic().
- CommentController.java: Xóa try-catch trong createComment(), getCommentsByComicId(), updateComment(), deleteComment(). Bỏ check auth thủ công.
- ComicRateController.java: Xóa try-catch trong rateComic(), getUserRating(). Bỏ check auth thủ công.
- ComicLikeController.java: Xóa try-catch trong toggleLike(), getLikeStatus(). Bỏ check auth thủ công.

6.2. Service cần sửa:
- AuthServiceImpl.java: Đổi RuntimeException sang BadRequestException (trùng username) và ResourceNotFoundException.
- ComicServiceImpl.java: Đổi RuntimeException sang ResourceNotFoundException và FileStorageException.
- CommentServiceImpl.java: Đổi RuntimeException sang ResourceNotFoundException và ForbiddenException.
- ComicRateServiceImpl.java: Đổi RuntimeException sang ResourceNotFoundException.
- ComicLikeServiceImpl.java: Đổi RuntimeException sang ResourceNotFoundException.

6.3. Ảnh hưởng đến API Response:
- CÓ (Chuẩn hóa format lỗi). Khi lỗi xảy ra, API trả về cấu trúc JSON ErrorResponse đồng nhất thay vì chuỗi text thô.
- Các API thành công HOÀN TOÀN KHÔNG BỊ ẢNH HƯỞNG.

6.4. Ảnh hưởng đến Frontend:
- CÓ (Tích cực). Frontend khi nhận lỗi (HTTP 4xx/5xx) sẽ đọc message từ `error.response.data.message` (hoặc `error.response.data.validationErrors`) thay vì đọc string plain.
- Giúp Frontend hiển thị giao diện thông báo lỗi chuẩn xác, nhất quán và chuyên nghiệp.
